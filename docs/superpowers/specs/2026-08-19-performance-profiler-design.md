# 性能统计模块拆分设计

## 目标

将离线流水线的性能计时、汇总、控制台展示和文件保存集中到独立模块，降低 `apps/offline_scan.py` 的职责和体积，同时修复现有计时边界与指标命名歧义。重构不得改变检测、跟踪、关键帧、关联、计数及报告内容。

## 模块边界

新增 `core/performance_profiler.py`，提供 `PerformanceProfiler`。该类负责：

- 记录 Pipeline 起始时间、阶段累计耗时和成功调用次数；
- 提供可选计时上下文，关闭统计时保持低开销；
- 包装特征匹配器并单独统计匹配时间；
- 计算阶段平均耗时、Wall%、未统计耗时和计时重叠；
- 生成控制台文本，并保存 `performance.json` 与 `performance.txt`。

`offline_scan.py` 仅创建 profiler、在业务边界调用计时器，并在结束时输出结果。原有 `DebugStats` 继续服务调试流水线和调试事件，不承担新的离线性能报告职责。

## 计时口径

- `Pipeline wall time` 从 `run_pipeline()` 入口开始，到性能快照生成前结束，包含配置加载、初始化、逐帧处理和产物生成，不包含 Python 进程启动与模块导入。
- `Initialization` 从入口开始，到所有流水线模块构造完成为止，因此包含配置读取。
- 视频解码只在成功返回一帧后增加调用次数；EOF 探测耗时计入未统计开销，不伪装成成功解码。
- 特征匹配作为嵌套阶段单独计时；关键帧决策、Recovery 和尾窗选择记录扣除匹配后的自身耗时，避免重复累计。
- Recovery 成功后的图更新、L1、融合、Tracker、投影和关联分别进入既有阶段。
- 尾窗接受关键帧后的图更新、L1、融合、投影和关联分别进入既有阶段。
- 当阶段总和超过墙钟时间时，报告负的未统计差额并给出 `timing_overlap_detected`，不再截断为零或静默显示 100%。

## 输出契约

启用性能统计时，在 `<output_dir>/reports/` 生成：

- `performance.json`：稳定的机器可读结构，包含 schema 版本、帧数、墙钟耗时、FPS、各阶段 total/calls/average/wall_percent、未统计差额、覆盖率和重叠标记；
- `performance.txt`：与控制台相同的可读表格。

关闭性能统计时不生成上述文件。已有 `report.json` 和 `report.csv` 内容不变。性能文件自身的写盘发生在快照之后，不计入该快照，避免报告自引用计时。

## 错误处理

- 输出目录由 profiler 创建；写盘异常正常向上抛出，避免静默丢失论文实验数据。
- 未知阶段名立即抛出 `ValueError`，防止拼写错误产生无效指标。
- 零墙钟时间和零调用阶段安全输出零值。

## 测试策略

- 单元测试覆盖阶段累计、平均值、EOF 成功计数、关闭统计、重叠告警和 JSON/TXT 保存。
- 流水线回归测试覆盖 Recovery 与尾窗成功路径的阶段归类。
- 保留现有性能测试的行为要求，并迁移导入位置。
- 最后运行完整 pytest 套件，确认识别与计数逻辑未改变。

## 非目标

本次不缓存 SIFT 特征，不优化 Global Mosaic 的重复 warp，也不修改任何识别和关联配置。这些性能优化后续以独立实验进行，便于与 baseline 公平比较。
